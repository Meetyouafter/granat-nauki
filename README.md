Пользователь заходит на сайт.
Next.js делает SSR/SSG или вызывает API Node.js (NestJS) для получения:
статей блога
отзывов
услуг

NestJS делает запросы в PostgreSQL и возвращает JSON.

Next.js отображает данные на страницах.

Весь основной сайт (публичная часть + админка) — на одном стеке: Next.js + React + TS на фронте, NestJS + TS на бэке. Без Angular — админка это защищённые роуты в том же Next.js-приложении, один деплой, один язык.

Отдельно — Telegram-бот на Go, не влияет на работу сайта, если упадёт или переписывается.

Админка
Часть Next.js-приложения (защищённые роуты, тот же React/TS), не отдельный сервис.
Администратор заходит на /admin, фронт ходит в тот же NestJS API с JWT-токеном.

Управление услугами	Жена сама может менять услуги, цены, описание без правки кода
Блог / статьи	Добавление и редактирование советов, статей, видео
Отзывы	Добавление новых отзывов, возможность модерации
Контактная форма	Отправка сообщений на email или сохранение в базе для статистики
Запись на консультацию	Отправка заявки, сохранение даты и времени в базе
Статистика	Отслеживание популярности статей и услуг

JWT аутентификация и авторизация
NestJS: REST API, CRUD-эндпоинты

Работа с загрузкой файлов (Cloudinary/S3) через API
CORS, безопасные запросы между фронтом и бэком

Бот (Go, песочница для новых технологий)
Отдельный сервис, общается с NestJS-бэком по HTTP (внутренний API), не лезет в БД напрямую.
Если бот упал или переписывается — на сайт и админку это не влияет.

🔹 Модерация отзывов прямо из Telegram (одобрить/отклонить кнопкой)
🔹 Еженедельный дайджест статистики (популярные статьи/услуги) владельцу в Telegram
