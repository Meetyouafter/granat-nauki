### 2. Разделение публичного и админского API

**Проблема.** `GET /faq?locale=ru` обслуживает одновременно публичный сайт и админку.
Из-за этого внутреннее поле `translationStatus` (статус перевода, состояние интеграции
с DeepL) утекает наружу всем посетителям сайта. Плюс невозможно повесить гард:
ручка нужна и анонимам, и админу.

**Что сделать.**

- [ ] Развести на `GET /faq` (публичный, без `translationStatus`) и
      `GET /admin/faq` + `PUT /admin/faq` (под гардом, со статусами).
- [ ] Разные DTO ответа: `FaqItemDto` (публичный) и `AdminFaqItemDto` (со статусом),
      чтобы поле не могло случайно просочиться. Сейчас `FaqService.toDto` заполняет
      `translationStatus` только для `ru` — это работает, но держится на договорённости,
      а не на типе.
- [ ] Обновить `admin/src/entities/faq/api/*` и `frontend` на новые пути.

### 3. Гонка в кроне переводов

**Проблема.** `TranslationStatus.PROCESSING` объявлен в
`src/constants/translation-status.enum.ts`, но не используется нигде.
`TranslationService.handleTranslate` берёт записи в статусе `PENDING` и не помечает их
занятыми. При пересечении запусков (перевод дольше часа) или на двух инстансах одна
запись переведётся дважды — лишний расход квоты DeepL и лишние запросы.

**Что сделать.**

- [ ] Помечать выбранную пачку `PROCESSING` в отдельной транзакции до вызова DeepL
      (`UPDATE ... WHERE status = 'pending' ... RETURNING id`, либо
      `SELECT ... FOR UPDATE SKIP LOCKED`).
- [ ] Возвращать в `PENDING`/`FAILED` по результату.
- [ ] Отдельно — «отвисание»: если процесс упал в `PROCESSING`, запись зависнет навсегда.
      Нужен таймаут по `updatedAt`.
- [ ] Либо, если одного инстанса достаточно навсегда, убрать `PROCESSING` из enum,
      чтобы не создавать иллюзию защиты.
